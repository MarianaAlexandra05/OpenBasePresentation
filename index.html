EL SALTO GENERACIONAL

¿Por qué la Versión Nativa de Windows Cambia Todo?

Compara la antigua aproximación basada en contenedores Docker contra la nueva arquitectura Win32 optimizada.

Antes (Docker / WSL2)

Aproximación por Contenedor

  • Requiere Docker Desktop: Consumo forzado de 3.5GB+ de RAM en la máquina virtual Linux.
  • Latencia de Audio Alta (~350ms): El audio debía puentearse entre Windows y la VM de Docker.
  • Conflictos de Rutas de Archivos: Traducción compleja entre rutas de Windows C:\... y /mnt/c/....
  • Sin Supervisor de Servicios: Si se cerraba la terminal, todos los agentes morían de inmediato.
Ahora (Nativo Windows v2.4)

Arquitectura 100% Nativa Win32

  • Cero Docker ni Máquinas Virtuales: Ejecución directa en Windows con menos de 45MB de memoria RAM.
  • Audio en Tiempo Real (<20ms): Acceso directo a micrófonos y altavoces mediante WASAPI nativo.
  • Rutas y PowerShell Nativas: Integración transparente con PowerShell 7, CMD y VS Code sin conversiones.
  • Supervisor Win32 Desacoplado: Procesos background que sobreviven cierres de terminal con PID locks nativos.

PILARES TÉCNICOS

Construido Específicamente para el Ecosistema Windows

No es una simple adaptación: cada módulo del runtime fue rediseñado para aprovechar las APIs del kernel de Windows.

Supervisor de Servicios Win32 Desacoplado

Reemplazo nativo de launchd y systemd. Utiliza descriptores JSON en ~/.openbase/windows-units y procesos detached con flags CREATE_NEW_PROCESS_GROUP para garantizar disponibilidad 24/7.

openbase_coder_cli.services.windows

Servidor de Voz LiveKit Nativo (.exe)

Descarga y gestiona automáticamente el binario oficial de livekit-server.exe para Windows x86_64 y ARM64. Provee WebRTC de grado de producción y salas de audio bidireccionales en tu propio host.

livekit_install._download_from_livekit_windows_release

Integración Nativa con PowerShell 7 & Terminal

Comandos de consola optimizados para PowerShell y CMD. Normalización de separadores de ruta (\ vs /) sin escapes accidentales y soporte para terminaciones ejecutables .exe, .cmd y .bat.

openbase_coder_cli.platforms.executable_suffixes

Sonda de Procesos y Sockets Win32 (Netstat)

Detección de puertos y estado de procesos directamente con la API de Windows OpenProcess y netstat -ano, eliminando cualquier dependencia de herramientas UNIX como lsof o ps.

openbase_coder_cli.process_probe.pid_alive

Sincronización y Control Remoto con Móviles

Empareja tu iPhone o teléfono Android con tu PC Windows a través de Tailscale o red local. Controla llamadas de voz, aprueba permisos de ejecución y revisa diffs mientras estás lejos de tu escritorio.

Tailscale LAN Mesh + WebSocket Bridge

Bloqueo de Archivos Concurrente (msvcrt.locking)

Manejo seguro de concurrencia para múltiples agentes trabajando en paralelo. Implementación especializada con reintentos y _windows_flock para evitar bloqueos en el sistema de archivos NTFS.

openbase_coder_cli.file_lock._windows_flock

INSTALACIÓN SENCILLA

Empieza a Usar Openbase Coder en Windows

Elige el método que mejor se adapte a tu flujo de trabajo: instalador de un clic o mediante herramientas de línea de comandos.

1

Instala la CLI nativa con uv

Ejecuta en PowerShell como tu usuario normal (sin privilegios de administrador requeridos):

uv tool install openbase-coder
2

Ejecuta el Asistente de Configuración Guiada

Configura tu proveedor de voz (Cartesia/ElevenLabs), backend de código y autenticación:

openbase-coder setup
3

Inicia los Servicios en Segundo Plano

El supervisor Win32 levantará LiveKit Server y la API automáticamente:

openbase-coder services start

Openbase Coder v2.4.0 — Windows Native Release Notes

Publicado: 16 de Agosto, 2026

🚀 Principales Novedades en Windows

  • Nuevo supervisor Win32 (services\windows.py): Administrador de procesos en segundo plano desacoplado que utiliza JSON descriptors en ~/.openbase/windows-units.
  • Gestor Automático de Binario LiveKit: Descarga y verificación automatizada de livekit-server.exe oficial para Windows.
  • Sonda de Procesos Nativa (process_probe.py): Consulta directa al kernel mediante Win32 OpenProcess y GetExitCodeProcess.
  • Bloqueo de Archivos Concurrente (file_lock.py): Implementación optimizada con msvcrt.locking y reintentos adaptativos en Windows.
  • Compatibilidad de Rutas y Ejecutables: Normalización de separadores y sufijos .exe, .cmd, .bat para virtualenvs de Windows (Scripts\).
  • Diagnóstico openbase-coder doctor: Inspección de sockets y puertos mediante netstat -ano en lugar de lsof.
